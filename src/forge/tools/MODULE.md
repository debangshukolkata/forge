# tools

The tool implementations the agent can call (files, search, shell wrappers, KB, DB, web, browser, verify, vision, Mode B, learning) and the registry that lists them.

- **Web (D-209):** `web.py` (the tools and search providers), `web_chain.py` (fetch stages), `web_guard.py` (address policy),
  `web_extract.py` (HTML/PDF to text), `web_render.py` (read-only headless browser). A fetch never ends in nothing: see DECISIONS D-209.
- **Web UI quality (D-245..D-254):** `browser.py` (`browser_screenshot` scrolls the page so scroll reveals play, saves the picture, runs the style audit, flags a picture identical to another page's, takes `width`/`height`), `ui_audit.py` (the in-page audit: unstyled CSS framework, contrast with oklch/color-mix read through a canvas, overflow, default controls, see-through sticky bars, invisible form fields, clipped text, taste checks, plus a static source scan and `tailwind_setup_problem`), `show_app.py` (opens the running app after proving it is the app; tries 127.0.0.1, localhost and [::1]), `vision.py` (`view_image` now reports the image path so the chat can show it).
- **Depends on:** brand, config, db, designsystem, doctor, documents, environment, errors, knowledge, llm, net, memory, modeb, ooxml, parity, pdfs, safety, sheets, slides, toolkit, vision, workspace
- **Invariants:** Each tool has pydantic Args, a one-line summary() and a read_only flag. Errors become ToolResult(ok=False). Tools that start agents live in forge.agent, not here.
- **Tests:** test_context.py, test_contracts.py, test_db.py, test_frontend_setup.py, test_hardening.py (and others; see tests/)
- **Decisions:** docs/DECISIONS.md (search the module's feature names); layering is enforced by tests/test_module_boundaries.py.

Keep this file in step with the code: the `Depends on` line is checked against the real imports.
- **Pictures (D-326..D-328):** `imagegen.py` (`generate_image`, Gemini/Imagen on Vertex AI), `findimage.py` (`find_image`, `fetch_image`), `image_sources.py` (Iconify, Openverse, Wikimedia, NASA, Pexels, Unsplash, Pixabay with licence filter), `picture_library.py` (pictures kept for offline reuse); `scripts/dev/reach_smoke.py` checks what the machine can reach.
- **Fonts (D-330):** `fonts.py` (`find_font`, `fetch_font`), `font_sources.py` (Fontsource catalogue, licence filter, @font-face CSS); `slides/installed_fonts.py` tells which fonts this Windows computer has.
- **Archives and app keys (D-461, D-466):** `archive.py` (one tool: list or extract zip and tar into `.forge/inputs/<name>/` or a workspace folder, with entry, size and path limits) and `app_keys_tool.py` (`request_app_keys`; `request_app_secret`, D-569, D-570: values the user keeps in DebCraft's .env reach the commands by name, several at once, after one card). `ask_user` and `request_user_action` refuse to ask for a secret in the chat, for a restart of DebCraft or for a variable to be set where DebCraft can see it, and name these routes. `http_request` accepts a token saved with `Bearer`, tries the bare token when the API refuses the prefix and tries `DEVELOPMENT_INSTANCE_TOKEN` when no token was named (D-570), and uses the form an API accepted before (D-571). `handoff_review.py`: before a `request_user_action` card is shown, the reviewer role's model decides whether DebCraft can do the step itself; if so the card is held back and the model is told which tools to call (D-571). `ocr_image` and `ocr_pdf` are registered only when Tesseract is ready. A request carries at most 128 tools (D-462), now a hard stop only (see deferred tools).
- **Theme inspiration (D-492):** `theme_search.py` (`theme_search`: search, read-only study, clean-room check) and `theme_sources.py` (the public theme lists, GitHub and WordPress.org package reads, the facts a study keeps, the fingerprint and overlap). Skill `theme-inspiration`; protocol docs/THEME_CLEAN_ROOM.md.
- **Code intelligence (design doc section 3, option B):** `code_intel.py` (`find_definition`, `find_references`, `list_symbols`): exact Python lookups through the optional `jedi` package (extra `intel`), lazy import, read-only, workspace project only, capped; without jedi each tool returns the install hint.
- **Code outline (C11, D-498):** `code_outline.py` (`code_outline`): signatures and line numbers of a file or folder (Python by `ast`, other languages by pattern) and `callers` of a name; read-only, parses on demand, no index (D-156).
- **Deferred tools (D-561):** `deferred.py` (the groups of tools that are not sent until loaded: office files, PDF, page design, pictures, evals, notebooks, exact code lookups), `tool_search.py` (`tool_search`: lists them by name in its description and loads them by name, group or keyword), `registry.py` (`ToolRegistry(defer=True)` sends only core and loaded tools; `attach`, `is_waiting`, `loaded`). A skill loads tools with a `tools:` line in its header; the agent loop loads a deferred tool that is called directly, and restores loaded tools from the history of a reopened session. A new tool that is not needed in most sessions goes into a group in `deferred.py`.
- **Repository knowledge (D-563 to D-566):** `code_map_tool.py` (`code_map`; the store by repository; the index follows the user's own folder at session start and a project is answered for its own copy; the pinned map with recent changes and the topic index), `knowledge_tools.py` (`knowledge_search`, `knowledge_write`, the two reminders on `read_file`, the `/learn` request and status). Skill `learn-repository`. Not offered in a project without a repository (`registry.session_tools`).
- **Solving a requirement against the running system (D-568):** `http_request.py` (`http_request`: localhost only; `token_env` names a variable in DebCraft's .env whose value goes into the header, only names the user released (`DEVELOPMENT_INSTANCE_TOKEN`, more through `FORGE_REQUEST_TOKEN_NAMES`), read at call time, never shown; the answer's size in characters and tokens, the JSON parts by size, the whole body kept in a file), `db.py` (`db_copy_table`, `use_scratch_database`). Skill `solve-against-running-system`. Test bed: `tests/fixtures/agent_platform` (AgentHub). Tests: test_http_request.py, test_db_copy.py, test_live_running_system.py.
- **Edits and syntax checks (HW3, HW4, D-577, D-581):** `edit_match.py` (an `old_string` that differs only in indentation or trailing spaces is applied when exactly one block matches; the result says so), `diagnostics.py` (after each save: Python, SVG, JSON in-process; `node --check` for JavaScript and `ts_syntax_check.js` for TypeScript, both only through the sandboxed `execute`).
- **Conversations (D-582):** `conversation_recall.py` (`conversation_recall`, deferred group `conversations`: reads another conversation's requests and answers from its log, redacted; never the active one).
- **Run notes (D-597):** `http_request` writes a call that worked into the run notes; `conversation_recall` has `what="steps"` (the commands and calls that ran the system, from an earlier conversation's log).
- **Streamed answers (RS9, D-599):** `stream_summary.py` (pure: server-sent events or JSON lines, each with its arrival second, into an account: kinds, tool events in order, longest silence, errors, final answer); `http_request` `stream: true` uses it and keeps the whole stream in `.forge/tool_outputs`.
- **App logins (D-603):** `app_login.py` (`app_login`, deferred group `remote_apps`: a persistent Edge profile per environment, the user's steps, the token from a cookie or a header, renewed without a window); `http_request` asks once per host and project before a listed remote host, sends a store token only to its own host or localhost and signs in again once on a 401 or 403.
- **Changes to the development database (D-608, D-609):** `dev_db.py` (`dev_db_write`, `dev_db_undo`; deferred group `dev_database`, offered with the database tools). Each call checks the statement, plans it, shows the statement and the rows before and after on a red card (`ToolContext.confirm_danger`, set by the session host: a `question_asked` event with `danger: true`, no recommended option, approved only by a click on the first option; a headless run always declines) and commits after the click. Where the user cannot be asked (a subagent) the tool refuses. The result gives the model counts and keys, not values. Tests: test_dev_db_write.py, test_web_danger_card_e2e.py.
- **The copied application on the development database (D-610):** `use_dev_database` (red card once per session, starts `db.dev_proxy.DevProxy`, sets the application's settings; empty `variables` switches back) and `dev_db_activity` (the report), both in `dev_db.py`, group `dev_database`. The session host publishes the report as a `dev_db_activity` notice after every turn and closes the relay at session end.
- **A secret from an API's answer to the commands (D-611):** `kept_secrets.py` and the `keep_secret` option of `http_request`: the value at a path of the JSON answer is masked, blanked in the answer and set for the session's commands (`ShellSession.kept_env`) after the user agreed once per name and project. Tests: test_keep_secret.py.
- **Where a table is (D-614):** `db.py`: `db_query` and `db_schema` answer "does not exist" / "No tables found" with the schemas that hold the table (or that hold tables at all); `db_request` refuses one plain INSERT or UPDATE when `dev_db_write` can make it. Tests: test_dev_db_write.py.
