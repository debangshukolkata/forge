Create `patching.py` (standard library only; do not call `patch`, `git` or `difflib.restore`): a parser and applier for **unified diffs** of one text file.

**Types and functions**
- `Hunk` (a dataclass): `old_start: int`, `old_count: int`, `new_start: int`, `new_count: int`, `lines: list[tuple[str, str]]` (each `(tag, text)` with tag `" "` for context, `"-"` for a removed line, `"+"` for an added line; `text` has no line terminator), `old_no_newline: bool = False`, `new_no_newline: bool = False`.
- `PatchFormatError(ValueError)`: the patch itself is malformed. `PatchConflictError(ValueError)`: the patch is fine but does not fit the text. It has the attributes `hunk` (1-based number of the hunk), `line` (1-based line number in the text where the first mismatch is), `expected` (the line text the patch wanted) and `found` (the line text that is there, or `None` when the text ended before that line).
- `parse_patch(patch: str) -> list[Hunk]`
- `apply_patch(text: str, patch: str, reverse: bool = False) -> str` returns the patched text; it never modifies anything and either applies every hunk or raises.

**Line terminators.** A line ends with `\n` or `\r\n`; a lone `\r` is part of the line (do not use `str.splitlines`, which also splits on other characters). In the patch, terminators are not part of a line's text, so a patch with `\r\n` endings works like one with `\n`. Context and removed lines are compared with the text's lines *without* their terminators; everything else (including trailing spaces and tabs) must match exactly. Kept lines keep their own terminator; added lines use the terminator of the text's first line (`\r\n` or `\n`; `\n` if the text has no terminator at all).

**Patch syntax.** Everything before the first `@@` line (such as `diff --git`, `index`, `---` and `+++` lines) is ignored. A hunk starts with `@@ -<start>[,<count>] +<start>[,<count>] @@` optionally followed by a space and any section text; a missing count means 1; anything else starting with `@@` that does not fit is a `PatchFormatError`. The body lines start with a space (context), `-` or `+`; a completely empty line inside a hunk counts as a context line with empty text. The body ends once it has exactly `old_count` old lines (context plus removed) and `new_count` new lines (context plus added); a body that is too short before the next `@@` or the end of the patch, or that would run past the counts, is a `PatchFormatError`. A line starting with a backslash (`\ No newline at end of file`) belongs to the line before it: after a `-` line it means the text's last line had no terminator (`old_no_newline`), after a `+` line the patched text's last line has none (`new_no_newline`), after a context line both. After a hunk only further hunks, backslash lines and blank lines may follow; any other line is a `PatchFormatError`. A patch without any hunk changes nothing.

**Applying.** Positions are line numbers in the original text and are exact: there is no searching for the context elsewhere, no offset and no fuzz. For a hunk with `old_count > 0`, the hunk starts at original line `old_start`; for `old_count == 0` the new lines are inserted after original line `old_start` (so `-0,0` inserts at the very beginning, and `old_start` equal to the number of lines appends). The context and removed lines must equal the original lines there, or `PatchConflictError` is raised (a hunk that reaches past the end of the text conflicts with `found=None`); a `old_start` beyond the end of the text (for count 0: beyond the line count) is a conflict as well. Hunks must be in increasing order and must not overlap, otherwise `PatchFormatError`. If the last line of the result has no terminator because of `new_no_newline`, it stays without; if lines follow an unterminated line, it gets a terminator. `new_start` is not checked.

`reverse=True` applies the patch backwards (added lines are removed and removed lines added, using the new-side positions).

Write tests for it too (`test_patching.py`). Use only the standard library.
