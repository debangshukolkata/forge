# Risk register (living)

L = likelihood, I = impact (H/M/L). Status: Open / Mitigating / Closed.

| # | Risk | L | I | Mitigation | Status |
|---|---|---|---|---|---|
| R1 | Scope is very large (~30–50k LOC, 17 milestones); months, not weeks. | H | H | Usable core = M0–M9 (Mode A end-to-end in the browser); later milestones are increments. | Open |
| R2 | Write jail can't be airtight through the shell (aliases, `-EncodedCommand`, Python one-liners). File tools are fully jailed; shell is best-effort. | M | H | Classifier + approval (D-044) + OS-enforced low-integrity sandbox (D-050): writes outside repo/ and scratch folders are refused by Windows (tested). Residual: fallback mode on machines where the sandbox can't start. | Mitigated |
| R3 | App runs against the shared dev DB could modify real data (unqualified tables fall through to `public`; app uses its own credentials). | M→L | Critical | D-005: local Postgres first; remote only with `search_path` = scratch only; refuse runs when a touched table isn't in scratch. | Mitigating |
| R4 | Bootstrap credentials can leak in tracebacks; Forge can't redact values it never sees. | M | H | Pattern redaction + value capture in a wrapper process whose values never return to the model. | Open |
| R5 | tiktoken needs internet on first use. | H | M | D-015: vendor the encoding file. | Mitigating |
| R6 | Tool-calling behaviour differs from Claude; "parity" is feature parity, not quality parity. Dev key serves GPT-4.1 (verified live), while the office target is GPT-5 — behaviour and capabilities (reasoning effort) differ between build and target. | H | M | Strict schemas, edit-failure hints, live eval suite early; context window and capabilities from config; report the actual model in every milestone. | Open |
| R7 | Corporate blockers: Vertex ADC/gcloud, localhost WebSocket blocked, AppLocker on embedded Postgres, TLS-inspecting proxy. | H | M | `forge doctor` checks each; SSE fallback; terminal fallback; `truststore` option; Gemini optional. | Open |
| R8 | Mode B stubs prove less than they seem; exact host versions may be unavailable offline. | H | M | Contract tests; "verified against stubs" wording; closest-version fallback recorded in ASSUMPTIONS.md. | Open |
| R9 | LLM cost overruns (KB builds, eval loops, reviewer, and now live tests with no FakeLLM). | M | M | Cost estimates before KB builds/evals; per-phase caps; live tests selectable with `-m live`; costs reported per milestone. | Open |
| R10 | Data governance: code, schemas, snippets, images sent to Azure. | M | H | Enterprise endpoints only; Mode B sensitive terms; sensitive-sample rules. | Open |
| R11 | PowerShell 5.1 quirks (encoding, exit codes, output framing in a persistent session). | H | M | Sentinel-framed session, UTF-8 console, Windows-specific test set in M3. | Open |
| R12 | Live, non-deterministic acceptance tests (consequence of D-008) can flake. | H | M | Judge on outcomes; run twice; keep deterministic tests for every invariant. | Open |
| R13 | Azure credentials for development are only stored encrypted inside Orchestrix's database. | H | M | User runs `scripts/dev/import_orchestrix_azure.py` (D-019); leak checks per D-016. | Mitigating |
| R14 | Build machine lacks Python 3.13 (target version). | H | M | Installed 3.13.15 per-user (D-006). | Closed |
| R15 | Pointing the app's config-table bootstrap at the local DB may need app-specific handling. | M | M | Design with the user in M7 (libpq env overrides vs repo test config). | Open |
| R16 | Built and tested against gpt-5.1 (+ gpt-4.1), deployed against the office GPT-5 deployment: prompts/tool behaviour tuned on one model may behave differently on the other. | M | M | gpt-5.1 dev deployment found (D-024), so build and target are the same model family. Capabilities from config; `forge doctor` reports the served model; re-run the live suite on the office deployment at M11. | Mitigating |
| R17 | If a stream fails part-way and is retried, text already shown is streamed again. | M | L | Retry notice is shown in the UI; M3 will mark the restarted stream so UIs replace the partial text. | Open |
| R18 | openai SDK depends on `httpx2`, a fork; SDK upgrades may change the transport again. | M | L | Pin openai in the wheelhouse; transport-level tests catch breakage. | Open |
| R19 | The import shim (sitecustomize) could interact with a host's own sitecustomize. | L | M | Used only when shadowing is detected; chains to the host's sitecustomize; re-verified after install. | Mitigating |
| R20 | output/'s "before" text for files changed outside the writer falls back to the original repo, which may have changed since the copy. | L | L | /sync (spec §6.5) refreshes the baseline; noted in CHANGES.md generation. | Open |
| R21 | Forge's own `-EncodedCommand` wrapper may be flagged by corporate endpoint security (EDR) as suspicious. | M | M | Test on the office laptop early; fallback option: write the wrapper to .forge/tmp and run with -File if execution policy allows. | Open |
| R22 | PowerShell 5.1 start-up adds 0.5–2 s per command. | H | L | Acceptable; tests/lint are few per task. Revisit with a warm process pool if it hurts. | Open |
| R23 | The classifier can misjudge unusual PowerShell (false 'safe'). | M | L | Unknown → ask; blocked list; the sandbox (D-050) makes misjudged writes harmless. | Mitigated |
| R24 | Sandboxed apps can't write outside the workspace (e.g. a log folder, user caches), which may look like app bugs. | M | L | Clear 'access denied' in output; the model is told commands are sandboxed (M4 system prompt); user can set shell.sandbox: off. | Open |
| R25 | Corporate security software may block or flag low-integrity process creation. | L | M | Automatic fallback with a notice; verify on the office laptop. | Open |
| R26 | In extreme windows (~5k tokens left for history) the model re-reads files after frequent summaries (seen up to 5 times per file). | M | L | D-055 bounded it (was a 40-step loop); real windows are 272k; M8's stuck detector stops repeated identical calls. | Mitigating |
| R27 | The SQL guard is a tokenizer, not a full Postgres parser; an unusual construct could slip past it. | L | H | Second layer on the server: read-only sessions (default_transaction_read_only), search_path = scratch only, timeouts; guard tests cover known bypasses. | Mitigating |
| R28 | An app whose DSN names its own schema (search_path in the DSN, or public.x in code) bypasses PGOPTIONS and could touch real tables. | M | H | KB flags hardcoded schema names; the local DB is the default target; the remote dev DB is read-only for Forge. Check to refuse such runs is an open M7/M8 item. | Open |
| R29 | Stuck detection can fire on legitimate work (e.g. re-running the same test while waiting for a background app). | M | L | Level 1 is only a note; repeated calls are counted only with no edit in between; thresholds are constants to tune from live logs. | Open |
| R30 | The reviewer subagent adds a model run to every REVIEW round (cost, minutes), and its findings can be wrong. | M | L | At most 2 fix rounds, then findings are reported, not enforced; the test guard is deterministic. | Open |
| R31 | The web UI's session token appears in the first URL (browser command line, console output); another process of the same Windows user could read it and drive Forge. | L | M | 127.0.0.1 only, Host/Origin checks, token moved into an HttpOnly cookie at once, new token per run; same-user malware is outside the threat model. | Accepted |
| R32 | Diagnose runs the user's real test suite (on a copy): tests may call real services or the shared dev DB with the user's own configuration. | M | M | Sandboxed (no writes outside the copy); report states it ran their suite; `--no-run` gives the integrity check only. | Open |
| R33 | The sandbox label check parses icacls output ("Low Mandatory Level"); a non-English Windows would report "not labelled" and fall back to running without the sandbox (with a notice). | L | M | Office laptop is English; if needed, read the SACL via the Win32 API instead. | Open |
| R34 | Code-style values are not redacted (`api_key=config.x`, `token = get_token()`); a real secret shaped like a lower-case dotted identifier (`password=abc.def`) in such a line would pass. | L | M | Registered secret values are always masked regardless; .env-style and quoted values are masked. | Accepted |
